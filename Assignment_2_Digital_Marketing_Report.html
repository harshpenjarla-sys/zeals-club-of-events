Question 1: Blog Engine Architecture & Inbound Funnel 10 Marks

1.1 Problem Statement & Strategic Objective

In traditional collegiate ecosystems, student event announcements are predominantly broadcasted across ephemeral social media channels (e.g., class WhatsApp groups and Instagram stories). These platforms have an extremely short lifespan (< 18 hours), suffer from zero organic search discovery, and fail to capture students seeking hackathons, sports tournaments, and workshops via Google Search.

To build a self-sustaining, long-term student acquisition pipeline for Zeal College of Engineering & Research (ZCOER, Pune), we developed and deployed "Zeal Campus Pulse"—a specialized Content Marketing Blog engine seamlessly integrated into the production platform at https://zeals-club-of-events.vercel.app/.

Inbound Conversion Funnel Architecture
Google Organic Search / Social Traffic ➔ Zeal Campus Pulse Blog (/blog) ➔ High-Intent Topic Guides (/blog/:slug) ➔ Embedded Event CTA & 2-Click Pass Registration ➔ Dynamic QR Attendance Code

1.2 Technical Implementation of the Blog Engine

The blog system was engineered with a modular, highly resilient architecture using React 19, Vite 6, and Tailwind CSS:

  • Client-Side SPA Routing (/blog & /blog/:slug): Zero-latency page switching using hash routing synchronizers, fully compatible with Vercel edge caching and static sitemap crawlers.
  • Instant Client-Side Filtering: Live keyword search matching article titles, tags, content excerpts, and author names in real time without server lag.
  • Five Strategic Content Pillars: Categorized into Tech & AI, Digital Marketing, Event Guides, Cultural Highlights, and Sports & Fitness.
  • High-Resilience Fallback Data Engine: When remote APIs undergo sleeping or cold starts, the system serves pre-compiled official ZCOER articles instantly from fallbackData.js, guaranteeing 100% uptime.
  • Conversion Cross-Linking: Every technical article dynamically queries the database for matching events (e.g., the Hackathon guide connects to the TechZeal 2026 National Hackathon) and displays an interactive registration card.

Question 2: Technical SEO Conduction & Indexation 5 Marks

2.1 Resolution of the "Sitemap is HTML" Google Search Console Error

During Google Search Console integration, Googlebot triggered a critical crawl failure: "Sitemap is HTML: Your Sitemap appears to be an HTML page."

Root Cause Diagnosis: In Single Page Applications (SPAs) deployed on Vercel, catch-all rewrite rules (such as "source": "/(.*)") redirect all incoming HTTP GET requests to /index.html so React Router can process client-side paths. When sitemap.xml was requested by Googlebot, Vercel returned the compiled React HTML document with Content-Type: text/html instead of XML, causing Googlebot's XML parser to fail.

2.2 Step-by-Step Technical Remedy

  1. Engineered Pure Static XML Sitemap: Created frontend/public/sitemap.xml adhering strictly to the sitemaps.org v0.9 schema, containing explicit canonical URLs, update frequencies, and priority weights for all 32 college pages, clubs, events, and blogs.
  2. Configured Negative Lookahead Rewrites in vercel.json: 
    {
  "cleanUrls": false,
  "rewrites": [
    {
      "source": "/((?!.*\\..*).*)",
      "destination": "/index.html"
    }
  ]
}
    This regex guarantees that any URI containing a dot (e.g., .xml, .txt, .html, .svg) bypasses the SPA rewrite and is delivered directly as a static file with its native MIME type.
  3. Standardized Robots Exclusion Protocol (robots.txt): 
    User-agent: *
Allow: /

Sitemap: https://zeals-club-of-events.vercel.app/sitemap.xml

2.3 Live HTTP Header Verification

The deployed endpoint was tested via terminal diagnostics, confirming pristine XML delivery:
